# AgentHub Local v1.5.5 详细实施方案 (Implementation Plan)

## 1. 任务背景与工程目标

本实施方案旨在将《企业级智能体完整架构方案》五层体系的核心认知、检索、图谱、输出自审、置信度治理与多模态能力一次性落地至 **AgentHub Local `v1.5.5`**。整个改造必须严格遵循以下四大工程铁律：

1. **零重型外置基础设施**：不引入 Chroma、Milvus、Qdrant、Neo4j 或 Celery/Redis，全部索引、三元组图谱与同步水位线收口于 `<workspace>/.agenthub/index.db` 与全局 `data/agenthub.db`（SQLite WAL 模式）。
2. **单文件分发体积受控**：严禁引入 PyTorch / TensorFlow；文本向量化通过“本机 Ollama/`llama-server` 优先复用 $\rightarrow$ 24MB ONNX INT8 量化模型 $\rightarrow$ 纯 FTS5 词法兜底”三级降级实现。
3. **零宿主代码库污染**：所有本地索引库、LRU 临时缓存均隔离在工作区 `.agenthub/` 隐藏目录或用户主目录 `~/.agenthub/` 下，绝不向用户源码目录写入额外文件。
4. **单色扁平 UI 规范**：前端新增配置弹窗、状态指示器与置信度徽标严格遵循单色扁平图标与纯色实底样式。

## 2. 分阶段实施路线与架构细节（共 6 个阶段）

### 阶段一：混合检索、轻量图 RAG 与智能体 RAG 核心引擎 (`backend/app/search/`)

#### 1.1 三级自适应 Embedding 后端 (`backend/app/search/embedding_provider.py`)
* **接口设计**：定义 `BaseEmbeddingProvider`（异步方法 `embed_texts(texts: list[str]) -> np.ndarray`、`model_id: str`、`dimension: int`、`is_available: bool`）。
* **三级探测与加载流水线 (`AdaptiveEmbeddingRouter`)**：
  1. **Tier 1（本地推理引擎复用）**：探测 `EnginePoolService` 中已激活的本地 `Ollama`（`/api/embeddings`）或 `llama-server`（`/v1/embeddings`），若存在可用 Embedding 模型（如 `nomic-embed-text`、`bge-m3`、`bge-small`），直接复用，额外内存占用为 `0 MB`。
  2. **Tier 2（轻量本地 ONNX 运行时）**：检查 `~/.agenthub/models/bge-small-zh-v1.5-int8/` 是否存在 `model_quantized.onnx` 与 `tokenizer.json`；若缺失且处于非离线模式，启动后台静默下载（带 SHA-256 校验与断点续传）；加载 `onnxruntime.InferenceSession`（限制线程数 `intra_op_num_threads=2` 防抢占主线程 CPU），输出 512 维 L2 归一化 `float32` 向量。
  3. **Tier 3（极限离线兜底）**：当上述两级均不可用时，返回 `NullEmbeddingProvider`（`is_available=False`），上层 `HybridSearchEngine` 自动切换为权重 `w_fts=1.0, w_vec=0.0` 的纯词法模式。

#### 1.2 AST 感知代码分块器 (`backend/app/search/ast_chunker.py`)
* 复用项目中已集成的 `tree-sitter` 解析器（支持 Python、TypeScript/JavaScript、Go、Rust、Java、C/C++）：
  * 按完整类（`class_definition`）与顶层/类内函数（`function_definition` / `method_definition`）边界切分，避免把完整函数腰斩；
  * 超长类按方法进一步拆解，并在每个切片头部自动注入上下文面包屑（例如：`# File: backend/app/agent/runtime.py | Class: AgentRuntime | Method: step`），显著提升自然语言查询与代码符号的语义对齐率；
  * 非代码文本（Markdown / 纯文本）按标题层级（`#` ~ `####`）与双换行段落边界切分（单切片上限 `800` 字符，重叠 `120` 字符）。

#### 1.3 SQLite 混合索引与后台异步队列 (`backend/app/search/hybrid_engine.py`)
* **存储与检索**：
  * 向量以 `vector.astype(np.float32).tobytes()` 存入 `hybrid_chunks.embedding_blob`；
  * 检索时先按 `pod_id` 过滤（及可选的 `source_type`、`include_archived`）加载候选切片的 `chunk_id` 与 `embedding_blob`，在内存中通过 `np.frombuffer` 拼装二维矩阵 $M \in \mathbb{R}^{N \times D}$，单次矩阵乘法 `scores = M @ query_vec` 完成全量余弦相似度计算（在 $N=20,000, D=512$ 规模下，纯 NumPy 点积耗时 `< 4 ms`）；
  * 同步执行 `hybrid_chunks_fts` 的 `MATCH` 词法召回，利用 RRF 公式融合两路排名，并应用动态意图权重路由。
* **非阻塞增量索引队列**：
  * 监听工作区文件变更事件与手动重建请求，将待向量化切片推入内存 `asyncio.Queue`；
  * 后台 Worker 以低优先级批处理（`batch_size=16`）计算向量并写入 SQLite，若检测到前台中高负载 LLM 推理正在进行，自动休眠让出 CPU/GPU 资源。

#### 1.4 轻量 SQLite 图 RAG (`backend/app/search/light_graph_rag.py`)
* **三元组抽取**：
  * 文档与知识库切片入库时，通过轻量规则模板 + 低成本小模型结构化抽取核心三元组 `(subject, predicate, object)` 写入 `knowledge_triples` 表（绑定 `pod_id`、`source_uri`、`authority_tier` 与 `effective_time`）。
* **SQLite 递归 CTE 多跳查询 (`query_knowledge_graph`)**：
  * 接收目标实体（或通过混合检索定位的 Top-2 起点实体），执行 SQLite `WITH RECURSIVE` 双向扩展查询（同时沿 `subject -> object` 出边和 `object -> subject` 入边扩展，硬上限 `max_hops <= 3`，单次最多返回 `30` 条高置信关系边），输出格式化的关联图谱路径及每条边的来源文档定位。

#### 1.5 智能体 RAG 多跳自检闭环 (`backend/app/search/agentic_retrieval.py`)
* 实现 `AgenticRetrievalLoop` 包装器（默认 `max_hops=3`）：
  * **Hop 1**：执行原始 Query 的混合检索 + 起点实体 1 跳图谱关联；
  * **覆盖度自检（Coverage Evaluator）**：检查召回切片中是否出现未展开的引用指针（如 `详见附件`、`参见第X章`、`另行通知`）或关键问句实体尚未被命中；
  * **Hop 2 ~ Hop 3**：若证据链不完整，自动生成补充子查询（Sub-Query）执行定向检索并合并去重切片池，直至证据充足或达到 `max_hops=3` 上限。

### 阶段二：多源知识冲突与时序权威仲裁 (`backend/app/search/conflict_resolver.py`)

1. **入库四维元数据判定流水线**：
   * `authority_tier` 自动定级规则：
     * 路径/标签明确配置为“正式发布库/知识库定稿区” $\rightarrow$ `Tier 1`；
     * 当前本地工作区普通活跃目录 $\rightarrow$ `Tier 2`；
     * 目录或文件名包含 `draft`、`草稿`、`temp`、`backup`、`archive`、`归档`、`旧版`、`废弃` 或明显历史年份前缀（如 `2023_`、`2024_`） $\rightarrow$ `Tier 3`。
   * `effective_time` 提取：优先从文档前 500 字符及文件名中正则匹配生效/修订日期（如 `2026年11月10日`、`2026-11-10`、`v2.4`），匹配失败时回退至文件 `mtime`。
   * `topic_cluster_id` 归一化：剥离文件名中的版本号（`_v1`、`_最终版`、`_修订`）、日期后缀与扩展名，计算规范化字符串指纹；入库或更新时自动扫描同 `pod_id` + 同 `topic_cluster_id` 下的所有文档，将 `effective_time` 最新的设为 `is_superseded = 0`，其余旧版置为 `is_superseded = 1`。
   * `content_hash` 跨源去重：若本地副本与云端微盘文档 SHA-256 完全一致，保留高权威等级记录，跳过冗余向量计算。
2. **检索重排与冲突显性化格式化**：
   * 在 RRF 基础上乘以 $W_{\text{authority}} \times W_{\text{freshness}}$；
   * 返回给 LLM 的每个切片统一包装为标准“时空身份证”头部：
     ```text
     [证据切片 #1 | 权威度: 正式发布(Tier 1) | 生效时间: 2026-11-10 | 版本状态: 最新版本 | 来源: wecom://竞赛管理库/2026竞赛规程_最终版.docx §3.2]
     ```
   * 当高分命中集合中同时出现同一 `topic_cluster_id` 的新旧版本，或不同 Tier 1/2 文档对同一数值/条件存在差异时，自动向响应上下文注入冲突审计提示指令，要求模型显性对比披露。

### 阶段三：CloudVFS 云盘虚拟知识库挂载 (`backend/app/vfs/`)

1. **抽象接口与水位线 (`backend/app/vfs/base.py`)**：
   * 定义 `CloudFileMeta(remote_uri, title, size, etag, mtime, mime_type)` 与 `CloudVFSProvider`（`list_changes(cursor)`、`download_stream(remote_uri)`、`test_connection()`）。
2. **三大云端适配器**：
   * `wecom_drive.py`：对接企业微信服务端微盘与文档 API（`gettoken` 自动缓存与提前 5 分钟刷新、递归列举指定 `spaceid` 文件夹树、下载文件流或导出智能文档 Markdown 内容）；
   * `webdav_provider.py`：基于标准 WebDAV `PROPFIND` 协议深度遍历目录，原生兼容 **Alist**、坚果云、群晖 NAS 与 Nextcloud；
   * `oss_provider.py`：支持标准 S3 / 阿里云 OSS / MinIO 签名请求，按 Bucket + Prefix 列举对象增量。
3. **流式章节抽取与按需 LRU 精读 (`backend/app/vfs/document_extractor.py`)**：
   * 使用轻量纯 Python 库（`pypdf` / `python-docx` / `openpyxl`）直接读取内存 `BytesIO` 流，按标题样式或 Excel Sheet 名抽取结构化章节树写入 `hybrid_chunks`，随后立即关闭流释放内存；
   * `read_cloud_wiki_section(remote_uri, section_path)` 命中时，优先查询 `~/.agenthub/cache/cloud_vfs/` 下的 24 小时 TTL LRU 缓存，未命中再从云端拉取单文件提取目标章节。

### 阶段四：输出前自我批评与动态置信度门控 (`backend/app/governance/`)

1. **输出前自我批评 (`backend/app/governance/self_critique.py`)**：
   * 触发条件：`GroundingConfig.strict == True` 且本轮会话执行过检索（`workspace_hybrid_search` / `search_cloud_wiki` / `query_knowledge_graph`）或外部数据工具；
   * 审查逻辑：构造独立 Critic 提示词，将“用户原始问题 + 原始检索证据切片 + 模型草拟回复”送入模型进行快速结构化核验（输出 JSON：`{"passed": bool, "issues": list[str], "revision_hint": str}`），重点检查数字、日期、金额、条件约束是否篡改或遗漏；
   * 若 `passed == False`，将 `revision_hint` 注入内部修订轮次重新生成最终回复（最多触发 1 次，防止死循环）。
2. **动态置信度评分与 HITL 门控 (`backend/app/governance/confidence_evaluator.py`)**：
   * 汇总本轮检索最高分、版本冲突标记、Critic 校验状态与工具执行状态，计算 `confidence_score`（保留两位小数）及归因标签列表（`reasons`）；
   * 通过 SSE 事件 `confidence_report` 推送至前端渲染底部微徽标；
   * 当 `GroundingConfig.strict == True` 且 `confidence_score < 0.60` 时，触发 `PolicyInterceptor` 挂起事件 `low_confidence_confirmation`，向前端发送结构化确认请求（展示依据摘要与冲突原因），等待用户点击确认或补充指令后再继续。

### 阶段五：L5 经验库升级、无头浏览器与多模态管道

1. **L5 实战微经验语义升级 (`backend/app/memory/experience_store.py`)**：
   * 写入新经验时同步计算 `problem_signature + root_cause` 的 Embedding 存入 `experience_embeddings`；
   * 召回时将原有的三路正交词法打分与向量余弦相似度按 `0.45 : 0.55` RRF 融合，并保留历史复用成功 `+0.03` / 失败 `-0.12` 奖惩闭环。
2. **原生无头浏览器 (`backend/app/tools/browser_agent.py`)**：
   * 懒加载 Playwright Chromium 实例（闲置 5 分钟自动关闭释放内存）；
   * 提取精简无障碍树（过滤隐藏节点与纯装饰元素，为可交互节点分配短引用 ID 如 `@e1`, `@e2`），支持 `browser_inspect_page` 与 `browser_interact_action`；
   * 接入 `PolicyInterceptor`：`localhost` / `127.0.0.1` 及白名单域名走 L0；未在白名单的外部只读访问走 L1；涉及表单提交或敏感写操作触发 L2 15 秒审批卡。
3. **多模态原生解析 (`backend/app/multimodal/`)**：
   * `vision_extractor.py`：接收图片路径，调用当前可用多模态视觉模型提取结构化 Markdown 表格、关键字段与 OCR 文本，可选写入当前工作区 `hybrid_chunks`（`source_type='multimodal'`）；
   * `audio_transcriber.py`：封装 `faster-whisper`（`int8` 量化 `tiny` / `base` 模型），首次调用时检查 `~/.agenthub/models/whisper/` 缺失则自动下载，执行本地离线转写并返回分段文本。

### 阶段六：前端单色 UI 联动、全量回归测试与打包验收

1. **前端组件开发 (`frontend/src/components/`)**：
   * `CloudWikiMountModal.tsx`：云端知识库挂载配置弹窗（支持企微微盘、WebDAV、OSS 三种选项卡，测试连通性、选择权威等级 `Tier 1~3`、查看同步进度与一键同步按钮）；
   * `ConfidenceBadgeBar.tsx`：挂载在助手回复底部的单色极简状态栏，展示置信度分值（`0.00 ~ 1.00`）、警告提示及可展开的「引用来源与版本仲裁溯源折叠面板」；
   * `LowConfidenceConfirmCard.tsx`：当置信度 `< 0.60` 触发挂起时渲染的纯色实底人工确认卡片（支持「仍要采纳」、「要求补充检索」与「终止回答」）；
   * 全局遵循单色扁平图标与纯色实底视觉规范。
2. **自动化测试与打包验收**：
   * 编写覆盖检索、图谱、云盘、自审、置信度、浏览器与多模态的完整 `pytest` 用例；
   * 执行 `npm --prefix frontend run build` 并校验 PyInstaller 单文件构建体积增量 `< 35 MB`。
