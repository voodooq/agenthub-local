## 1. 功能概览与系统架构

GeminiHub Local v1.5.5 引入了**“双脑认知协同引擎（Dual-Brain Cognitive Engine）”**，将本地工程代码与企业云端规程制度紧密融合，具备自动解决制度冲突、自审修正虚构事实及毫秒级显存保护的能力。

```mermaid
graph TD
    User([用户自然语言提问 / 指令]) --> Router[智能意图与检索路由]
    
    subgraph 认知大脑与双脑检索
        Router --> Brain1[本地脑: AST 语法分块 + FTS5 Trigram]
        Router --> Brain2[云端脑: 微盘/WebDAV/OSS 规程 Wiki]
        Brain1 --> RRF[RRF 倒数排名融合 + 时序权威仲裁]
        Brain2 --> RRF
        RRF --> GraphRAG[SQLite CTE 多跳知识图谱推理]
    end
    
    subgraph 显存感知 ONNX 双会话
        RRF -.-> CPU_Session[常驻 CPU 会话 (<10ms 低延迟查询)]
        RRF -.-> Ephemeral_GPU[按需临时 GPU 会话 (大批次加速/768MB硬限额/15s自动销毁)]
    end
    
    subgraph 认知治理与自审修正
        GraphRAG --> Agent[大模型推理生成初步草案]
        Agent --> Critic{输出前自我批评核验}
        Critic -- 发现虚构数字/冲突 --> ReDraft[触发 1 次自动纠偏重写]
        ReDraft --> Agent
        Critic -- 通过 --> ConfEval[多维置信度综合评估]
        ConfEval -- 分数 < 0.60 --> HITL[低置信度确认卡片 - 人工审批]
        ConfEval -- 分数 >= 0.60 --> Output([直接安全交付用户])
    end
```

## 2. 本地工作区混合语义检索与代码切片

### 2.1 AST 语法感知分块特性
系统内置基于 Tree-sitter 的代码 AST 分块器（`AstChunker`），对 Python、TypeScript、Go、Rust、Java 等工程源码进行结构化解析：
* **拒绝腰斩函数**：按完整类（Class）和函数（Function）定义边界切分，保留上下文完整性。
* **面包屑头注入**：切片自动携带顶部导航标识（如 `[文件: auth.ts > class AuthService > method login]`），提升自然语言搜索匹配率。

### 2.2 如何在对话中使用检索
Agent 会根据您的对话意图自动调用 `workspace_hybrid_search`。您也可以使用指令显式要求 Agent 搜索：
* **日常搜索示例**：
  > “搜索一下工作区里关于 JWT Token 刷新和过期处理的实现代码。”
* **搜索包含废弃/历史版本**：
  > “帮我检索历史版本的数据库备份迁移逻辑（包含已归档记录）。”

## 3. 云端规程知识库挂载 (Cloud VFS Wiki)

v1.5.5 支持将企业正式规程、管理制度或云端文档虚拟挂载到本地知识库中，支持**企业微信微盘**、**标准 WebDAV** 与**阿里云 OSS**。

### 3.1 界面操作入口
1. 点击系统右上角或知识库区域的 **「挂载云端 Wiki」** 图标。
2. 弹出 `CloudWikiMountModal` 弹窗，支持 3 种存储协议：

#### 挂载配置参数说明
| 挂载类型 | 必填字段 | 示例 / 说明 |
| :--- | :--- | :--- |
| **企业微信微盘 (WeCom)** | `企业 CorpID`, `Secret`, `SpaceID` | 企业微信自建应用凭据与目标微盘空间 ID |
| **标准 WebDAV** | `服务地址 (Base URL)`, `用户名`, `密码`, `根路径` | 如坚果云、群晖 NAS、Nextcloud 的 WebDAV 端点 |
| **阿里云 OSS** | `Endpoint`, `Bucket`, `AccessKey`, `SecretKey` | 对象存储凭证与私有规程目录前缀 |

3. 填写后点击 **「测试连通性」**，验证网络通畅后点击 **「保存挂载」**。
4. 点击 **「一键增量同步脑索引」**，系统通过 ETag / Last-Modified 水位线拉取并增量切片，不重复消耗流量。

### 3.2 制度时序冲突仲裁与“时空身份证”
当云端存在多份制度版本（如《2024暂行条例》与《2026正式规范》）且内容冲突时，系统自动识别并优先采信高权威度、最新发布版，同时输出**时空身份证**披露：

```markdown
⚠️ 检出制度冲突警示：
检测到《差旅费用管理办法》存在新旧版本冲突（旧版：2024-03-01；新版：2026-01-15）。
根据时序仲裁规则，已优先采信最新正式发布版本规定（每日住宿上限 800 元），历史废止规定（500 元）已自动降权。

[时空身份证]
- 规程来源: wecom://space_hr/2026_travel_rules.docx § 住宿标准
- 权威等级: Tier 1 (正式发布制度) | 生效时间: 2026-01-15
- 仲裁置信度: 0.96
```

## 4. 知识图谱多跳推理 (Light Graph RAG)

系统内置纯 SQLite 递归 CTE 图谱引擎，专门用于梳理组织归属、历任对接人、多方兼项限制等网状关联。

### 4.1 智能起点双向锚定
无需严格输入特定实体 ID，支持直接使用**自然语言长句**提问：
* **示例提问**：
  > “跨境电商项目的审批负责人是谁？他同时还兼任了哪些项目的主管？”
  > “查询李工的所有上下级对接关系链。”

系统内部通过 `find_anchor_entities` 自动从提问句中提取出关键实体（如“跨境电商项目”），并沿着出边与入边自动展开 2~3 跳子图。

### 4.2 图谱预览接口
您可以通过 API 获取可视化节点网络数据：
```http
GET /api/v1/knowledge/graph?seed=跨境电商项目&max_hops=2
```
返回节点（Nodes）与关系边（Edges）列表，支持在前端展示拓扑网络。

## 5. 三级自适应 Embedding 与显存加速策略

针对本地部署消费级显卡（如 RTX 4060 8GB、RTX 4070 12GB、Apple Silicon 或纯 CPU 环境），系统实现了显存零抢占与智能按需调度。

### 5.1 三级自适应后端
1. **Tier 1 (本地 Server 嗅探)**：若检测到本地运行中的 Ollama 或 llama-server，自动借用其嵌入模型，**0 额外显存消耗**。
2. **Tier 2 (内嵌轻量 ONNX 双会话引擎)**：
   * **CPU 常驻会话**：单条查询及小批次（$< 64$ 切片）强制走 CPU，响应时间 $< 10\text{ ms}$，彻底消除 CUDA 冷启动开销；
   * **按需临时 GPU 会话**：仅在批量索引且空闲显存 $\ge 2.5\text{ GB}$ 时按需启动，显式硬限额 768MB，**闲置 15 秒自动回收销毁**，不抢占本地大模型显存；
   * **异常自愈**：遇显卡驱动异常或显存不足自动捕获并无缝平滑回退常驻 CPU，零报错中断。
3. **Tier 3 (纯词法回退)**：当环境极度受限时，由 BM25 / Okapi 全文索引兜底。

### 5.2 手动切换硬件加速策略
可通过 Python 代码或后端配置调整加速策略：
```python
from backend.app.search.embedding_provider import embedding_router

# 可选策略: "auto" (默认自适应), "cpu" (强制CPU), "gpu" (启用临时GPU加速), "directml" (Windows DirectML)
await embedding_router.set_device_policy("auto")
```

## 6. 认知自审重写与置信度治理卡片

### 6.1 输出前自我核对与 Re-draft 重写
在 Agent 准备输出最终结论前，系统会在后台静默执行事实审查：
1. **自审查验**：比对回答中的关键金额、数字、日期是否在检索到的证据切片中有出处；
2. **自动纠偏（Re-draft）**：若检出未佐证的编造数字或冲突条款，Agent 会在内部自动触发 **1 次重新草拟**，带上反思提示修正错误；
3. **透明可追溯**：界面会实时收到 `critique_redraft` 提示，让用户知晓系统正在进行自我修正。

### 6.2 置信度综合评估卡片
每个回答生成完毕后，底部会呈现结构化置信度信息：
* **四级置信度徽章**：
  * 🟢 **高置信度 (0.85 ~ 1.00)**：具备正式发布规程佐证，无任何矛盾。
  * 🟡 **中置信度 (0.70 ~ 0.84)**：具备工作区证据，或包含部分常识推论。
  * 🟠 **低置信度 (0.60 ~ 0.69)**：缺少直接明确证据，给出审慎提示。
  * 🔴 **高风险 (< 0.60)**：证据严重不足或检出冲突。
* **低置信度拦截卡点 (HITL)**：
  当综合评分低于 `0.60` 时，系统自动弹出 `LowConfidenceConfirmCard` 阻断卡片，列明扣分原因与证据盲区，由您确认后再放行执行下一步。

## 7. 多模态浏览器审查与离线语音转写

v1.5.5 补齐了桌面多模态交互闭环，让大模型具备网页审查、页面拟人化操作与音频解析能力。

### 7.1 无头浏览器审查与拟人化交互
Agent 可自主调度内置的 `browser_inspect_page` 与 `browser_interact_action` 工具：
* **网页审查指令**：
  > “打开 http://localhost:3000 查看当前页面的无障碍结构和控制台报错日志。”
* **拟人化交互指令**：
  > “在当前页面点击登录按钮，并在账号框中填入 test_user。”

#### 浏览器交互参数表
| 动作 (Action) | 目标 (Target) | 附加参数 (Text) | 说明 |
| :--- | :--- | :--- | :--- |
| `navigate` | 目标 URL | - | 页面跳转并等待 DOMContentLoaded |
| `click` | CSS 选择器 / 元素文本 | - | 点击指定元素并等待微动画完成 |
| `type` | 输入框选择器 | 拟填入文本内容 | 模拟键盘输入并触发变更事件 |
| `scroll` | 页面区域 | 滚动像素 (如 `600`) | 向下滚动指定像素高度 |

### 7.2 离线语音快速转写 (Audio Transcriber)
本地轻量语音识别模块采用 `faster-whisper`（INT8 量化）：
* **首次按需下载**：体积 $< 150\text{ MB}$，模型保存在 `~/.agenthub/models/whisper/`。
* **使用指令**：
  > “请将本工程目录下的 meeting_record.mp3 会议录音转写为文字。”
* **返回值**：带精确时间戳的结构化文本摘要。

## 8. 常见问题与排错指南

### Q1: 增量同步时提示“未找到匹配的有效挂载源”？
* **排查方法**：
  1. 检查 `~/.agenthub/cloud_mounts.json` 中配置的 `mount_id` 是否正确；
  2. 若挂载源已修改，在弹窗中重新点击“保存挂载”后再执行同步。

### Q2: 批量建索引时 GPU 显存没有被占用？
* **原理解释**：
  1. 系统设有显存防爆门控机制：单条实时查询和少于 64 个切片的小批次强制走常驻 CPU 会话（仅需 5~10ms，无需显存）；
  2. 仅当批量导入大文件（$\ge 64$ 切片）且空闲显存 $\ge 2.5\text{ GB}$ 时才启动临时 GPU 会话；
  3. 执行完毕 15 秒后显存会自动销毁释放，观察显存需在批量建索引进行中查看。

### Q3: 运行音频转写提示 `未安装 faster-whisper`？
* **解决方法**：
  `faster-whisper` 为按需可选扩展库。在终端中执行以下命令安装：
  ```powershell
  .venv\Scripts\pip.exe install faster-whisper
  ```

### Q4: 提示代码中有制度条款冲突时应该如何处理？
* 系统默认会采用权威度更高（正式发布库 Tier 1 > 本地工作区 Tier 2 > 历史草稿 Tier 3）且生效时间更新的版本；若您需要特定历史草稿的执行口径，可直接在指令中指定“请依据旧版暂行办法进行分析”。
