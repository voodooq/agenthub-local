## 1. Problem Statement（问题陈述与背景）

在 AgentHub Local `v1.5.0` 完成“后台长驻进程托管”与“只读并发子智能体”后，系统在复杂代码研读、多源企业知识管理、结果确定性治理与多模态感知方面仍存在四项核心工程短板，制约其在高严谨业务场景下的规模化使用：

1. **单轮纯词法检索无法应对语义泛化、多跳图谱关联与证据链残缺**：
   * 现有的 `SQLite FTS5 trigram` 引擎对精确函数名、报错码极其敏感，但面对跨语言意图（如用中文业务大白话搜索英文代码实现）或同义症状描述（如“端口被占”匹配历史经验中的 `EADDRINUSE`）时存在严重漏召，导致大量 L5 实战微经验处于“沉睡”状态。
   * 缺乏跨文档实体关系推理（图 RAG），无法回答涉及多跳关系链（如 `机构 -> 历任负责人 -> 历史约定 -> 竞赛规程条款`）的网状关联问题。
   * 缺乏“智能体 RAG（Agentic RAG）”自主追问闭环，当首次检索返回的切片引用了未命中的附件或关联规则时，模型未能自动改写 Query 发起二次/三次定向补全检索。
2. **云端企业知识库割裂与新旧版本冲突治理缺失**：
   * 团队规程、管理制度、历史标书散落在**企业微信微盘/知识库**、**WebDAV（Alist/坚果云/NAS）**与**对象存储（OSS/MinIO）**中。传统做法需全量下载至本地并手动整理，不仅占用本地磁盘，且云端文档修订后本地极易过时。
   * 本地草稿、旧版规程与云端最新正式发布版并存时，单纯依赖文本相似度打分会导致模型误用过时条款，产生严重的业务合规风险。
3. **缺乏无报错情况下的输出质量自审与低置信度拦截门控**：
   * 现有的 `Reflector` 机制仅在工具执行报错或返回非零退出码时触发；当工具调用正常但模型出现事实漏答、数字核对偏差或检索依据不足（低置信度）时，缺乏输出前自我批评（Self-Critique）与低置信度人工介入（HITL）确认门控。
4. **多模态（图像/语音）与原生网页观察验收能力偏弱**：
   * 日常业务中的复杂表格截图、银行回单照片、语音指令以及本地前端服务页面渲染验收缺乏原生轻量级统一管道，过度依赖外部 MCP 节点配置。

## 2. Solution（总体解决方案与架构设计）

AgentHub Local `v1.5.5` 严格恪守**“零外置重型依赖（无 PyTorch / 无外部图数据库与向量库服务 / 索引与图谱全收口于本地 SQLite WAL）”**与**“零宿主工程目录污染”**架构红线，一次性构建四大核心支柱：

### 2.1 四维一体本地检索大脑 (`HybridSearch` + `LightGraphRAG` + `AgenticRetrievalLoop`)
* **三级自适应 Embedding + RRF 混合检索**：
  * **Tier 1（零额外内存）**：优先探活并复用本机已运行的 `Ollama` 或 `llama-server` Embedding 端点；
  * **Tier 2（极轻量本地离线推理）**：若无本地推理服务，自动加载仅约 `24 MB` 的 INT8 量化 ONNX 模型（`bge-small-zh-v1.5-int8`，首次按需静默下载至 `~/.agenthub/models/`），结合原生 SQLite `BLOB` 与 NumPy 矩阵点积实现毫秒级向量召回；
  * **Tier 3（极限离线纯词法兜底）**：在无网且无本地模型缓存的极端环境下，无缝退化为增强型 `SQLite FTS5 trigram` 检索，确保零异常可用。
  * 结合 Tree-sitter **AST 语法边界代码分块**与动态查询意图权重路由，全面赋能代码检索与 L5 实战微经验库。
* **轻量 SQLite 图 RAG (`LightGraphRAG`)**：
  * 不引入 Neo4j，在 `<workspace>/.agenthub/index.db` 中建立 `knowledge_triples` 三元组关系表（`主体 -> 关系谓词 -> 客体 + 溯源 URI`）；
  * 检索时执行**“混合向量定位起点实体 $\rightarrow$ SQLite `WITH RECURSIVE` 2~3 跳子图扩展”**，输出结构化关系链。
* **智能体 RAG 多跳自检闭环 (`AgenticRetrievalLoop`)**：
  * 在复杂问答场景下封装最多 **3 跳（`max_hops=3`）**自主检索循环：每次检索后评估证据链覆盖度，若发现关键引用缺失（如正文中出现“详见附件二”或未覆盖的约束条件），自动提取缺失实体改写 Query 发起下一跳检索。
* **Pod 隔离索引底座**：
  * 在所有切片与图谱表中原生写入 `pod_id`（客户/群组隔离域）与 `org_entity_id`（机构主干实体 ID），为 `v1.6.0` 的“一客一专员（Account Agent Pods）”打通底层数据隔离地基。

### 2.2 存储与索引分离的云端 LLM Wiki 与冲突仲裁 (`CloudVFS` + `ConflictResolver`)
* **云盘虚拟文件系统 (`CloudVFSProvider`)**：
  * 支持无感挂载**企业微信微盘/知识库**、**通用 WebDAV（兼容 Alist / 坚果云 / 群晖 NAS）**与 **S3 / 阿里云 OSS / MinIO**。
  * **“云端存源文件、本地建脑”工作流**：后台增量协程通过 `ETag / mtime / file_sha` 嗅探云端变更，流式拉取文件至内存提取纯文本与章节大纲（Markdown / DOCX / PDF / XLSX），切片向量化写入本地 `index.db` 后立即销毁内存临时流（**阅后即焚，零本地文件堆积**）；Agent 检索命中后通过 `read_cloud_wiki_section` 按需拉取目标章节原文（带 24 小时 LRU 缓存）。
* **多源版本冲突与时序权威仲裁 (`ConflictResolver`)**：
  * **第一道防线（入库四维元数据打标）**：自动识别 `authority_tier`（`1=正式发布库`、`2=工作区当前态`、`3=草稿/归档旧版`）、提取业务生效时间戳 `effective_time`、生成归一化主题指纹 `topic_cluster_id` 自动识别新旧版本链，并基于 `content_hash` 实现跨源完全一致内容去重。
  * **第二道防线（权威与时间衰减重排）**：在 RRF 得分基础上叠加权威系数 $W_{\text{authority}}$ 与时间新鲜度因子 $W_{\text{freshness}}$，压低过期草稿排序。
  * **第三道防线（时空身份证与冲突显性披露）**：注入上下文的每个切片强制附带权威度、生效时间与版本状态头；若多份有效文档间存在数值或条款打架，强制在回答中向用户披露冲突明细并采信最新权威版本。

### 2.3 输出前自我批评与动态置信度门控 (`SelfCritiqueCritic` + `ConfidenceEvaluator`)
* **输出前自我批评节点 (`SelfCritiqueCritic`)**：
  * 在「严谨工作模式（`GroundingConfig.strict=True`）」且当前轮次调用过检索/数据工具时触发；
  * 在最终答案流式吐出前，运行独立的轻量级 Critic 校验（检查生成草稿中的数值、日期、金额、规则约束是否与检索切片严格一致，是否存在漏答），若检出事实矛盾或关键遗漏，在后台无感触发最多 **1 次重写修订（Re-draft）**。
* **多维动态置信度评分与 HITL 门控 (`ConfidenceEvaluator`)**：
  * 综合检索匹配度、版本权威一致性、Critic 校验结果与工具执行完整性，计算 `0.0 ~ 1.0` 的最终置信度分值；
  * 当置信度 $< 0.60$ 时，拦截直接采纳结论，弹出人工确认门控（`low_confidence_confirmation`）提示依据薄弱或存在版本冲突，交由人类决策。

### 2.4 原生无头浏览器与多模态解析管道 (`BrowserAgent` + `MultimodalPipeline`)
* **原生无头浏览器 (`BrowserAgent`)**：
  * 基于 Playwright 提取低 Token 消耗的无障碍树（Accessibility Tree）结构快照，支持在线最新技术文档查阅与本地前端页面渲染/控制台报错验收（内置域名白名单与表单提交 L2 15 秒审批拦截）。
* **多模态原生解析管道 (`MultimodalPipeline`)**：
  * **视觉结构化提取 (`VisionExtractor`)**：当用户上传或粘贴复杂表格截图、银行回单、报错截图时，自动路由至多模态模型提取结构化 Markdown 表格与关键实体并纳入混合索引；
  * **轻量离线语音转写 (`AudioTranscriber`)**：集成按需加载的 `faster-whisper`（`tiny` / `base` 量化版，首次使用时按需下载至 `~/.agenthub/models/`，不计入基础安装包体积），支持将语音文件转写为带时间戳文本并入库检索。

## 3. User Stories（用户故事与验收场景）

1. **跨语言语义代码检索**：作为开发者，我希望用中文业务大白话（例如“系统是怎么处理令牌刷新和断线重连的”）搜索代码库，能精准定位到对应的英文函数定义与精确起止行号。
2. **跨文档图谱关联推理**：作为项目协调人，我希望系统能基于纯 SQLite 知识图谱进行 2~3 跳关联推理（例如“查询某俱乐部历任对接人及其关联的历史特殊条款”），无需部署 Neo4j 等重型图数据库。
3. **智能体 RAG 自主追问补全**：作为 Agent，当首次检索的规程切片中出现“具体费用见附件三”而附件三不在当前结果中时，我能自动改写 Query 发起第二跳检索，直到凑齐完整证据链再生成回复。
4. **零重型依赖与离线可用性**：作为桌面端用户，我希望所有检索与图谱能力在无 PyTorch 环境下运行；当断网且无本地推理模型时，系统能无感降级为纯 FTS5 检索且零报错。
5. **云端企业知识库无感挂载**：作为团队管理者，我希望将企业微信微盘/知识库、WebDAV（Alist/NAS）或 OSS 目录挂载为虚拟 Cloud Wiki，不占用本地硬盘空间，且云端文件修改后本地自动增量更新索引。
6. **新旧版本仲裁与冲突预警**：作为合规敏感型用户，当本地旧草稿与企微正式发布版对同一费用标准描述不一致时，我希望系统优先采信最新正式版，同时在回复中明确提醒我旧草稿里存在不一致的旧数值。
7. **严谨模式下输出前自我批评**：作为业务负责人，在严谨工作模式下，我希望 Agent 在给出汇总结论前先对照原始检索切片自查数字与日期，避免出现前后矛盾或漏答。
8. **低置信度人工介入拦截**：作为风控敏感用户，我希望每条业务回答都展示动态置信度评分，当置信度低于 `0.60` 时自动触发人工确认拦截，防止模型盲目拍板。
9. **前端页面渲染自动验收**：作为全栈开发者，我希望 Agent 能直接启动无头浏览器访问 `http://localhost:3000`，通过无障碍树快照检查页面元素渲染与控制台报错日志。
10. **截图表格与语音指令解析**：作为日常办公人员，我希望直接发送报价单截图或语音备忘录给 Agent，系统能自动提取结构化 Markdown 表格或转写语音文字并存入可检索的知识库。
11. **客户/群组隔离索引底座**：作为 B2B 客户经理，我希望底层索引库原生支持 `pod_id` 与 `org_entity_id` 隔离字段，确保不同客户或项目群的资料检索绝对隔离、互不串味。

### 4.2 SQLite 数据库 Schema 完整定义 (`<workspace>/.agenthub/index.db` 与 `data/agenthub.db`)

```sql
-- ============================================================================
-- 1. 工作区局部索引库: <workspace>/.agenthub/index.db (WAL 模式)
-- ============================================================================

-- 1.1 统一混合检索切片表（兼容本地代码、本地文档与云端 Cloud Wiki，含 Pod 隔离底座）
CREATE TABLE IF NOT EXISTS hybrid_chunks (
    chunk_id         INTEGER PRIMARY KEY AUTOINCREMENT,
    source_type      TEXT NOT NULL DEFAULT 'local',   -- 'local' | 'wecom' | 'webdav' | 'oss' | 'multimodal'
    pod_id           TEXT NOT NULL DEFAULT 'global',  -- 客户/群组隔离域标识（为 v1.6.0 AccountPod 预留）
    org_entity_id    TEXT NOT NULL DEFAULT '',        -- 机构主干实体 ID（为跨对接人归集预留）
    remote_uri       TEXT NOT NULL,                   -- 相对路径或云端 URI (如 wecom://space_id/doc_id)
    title            TEXT NOT NULL,                   -- 文档/文件名
    section_path     TEXT DEFAULT '',                 -- 章节面包屑或 AST 符号签名路径
    start_line       INTEGER DEFAULT 0,
    end_line         INTEGER DEFAULT 0,
    content_text     TEXT NOT NULL,                   -- 切片纯文本（同步写入 FTS5 虚表）
    content_hash     TEXT NOT NULL,                   -- sha256(content_text)，跨源完全一致内容自动去重
    topic_cluster_id TEXT NOT NULL,                   -- 去除版本号/日期后的归一化主题指纹
    authority_tier   INTEGER NOT NULL DEFAULT 2,      -- 1=正式发布库, 2=当前工作区, 3=草稿/归档旧版
    effective_time   REAL NOT NULL,                   -- 业务生效时间戳或物理 mtime
    is_superseded    INTEGER NOT NULL DEFAULT 0,      -- 1=同主题下已被更新版本替代
    model_id         TEXT NOT NULL,                   -- Embedding 模型标识（切换模型自动触发重建）
    embedding_blob   BLOB,                            -- L2 归一化后的 float32 向量字节流（离线可为 NULL）
    updated_at       REAL NOT NULL,
    UNIQUE(pod_id, remote_uri, section_path, start_line)
);

CREATE INDEX IF NOT EXISTS idx_hybrid_chunks_pod_topic ON hybrid_chunks(pod_id, topic_cluster_id);
CREATE INDEX IF NOT EXISTS idx_hybrid_chunks_hash ON hybrid_chunks(content_hash);
CREATE INDEX IF NOT EXISTS idx_hybrid_chunks_source ON hybrid_chunks(source_type, pod_id);

-- 1.2 FTS5 词法全文检索虚表（与 hybrid_chunks 通过触发器保持同步）
CREATE VIRTUAL TABLE IF NOT EXISTS hybrid_chunks_fts USING fts5(
    title,
    section_path,
    content_text,
    content='hybrid_chunks',
    content_rowid='chunk_id',
    tokenize='trigram'
);

CREATE TRIGGER IF NOT EXISTS trg_hybrid_chunks_ai AFTER INSERT ON hybrid_chunks BEGIN
    INSERT INTO hybrid_chunks_fts(rowid, title, section_path, content_text)
    VALUES (new.chunk_id, new.title, new.section_path, new.content_text);
END;

CREATE TRIGGER IF NOT EXISTS trg_hybrid_chunks_ad AFTER DELETE ON hybrid_chunks BEGIN
    INSERT INTO hybrid_chunks_fts(hybrid_chunks_fts, rowid, title, section_path, content_text)
    VALUES ('delete', old.chunk_id, old.title, old.section_path, old.content_text);
END;

CREATE TRIGGER IF NOT EXISTS trg_hybrid_chunks_au AFTER UPDATE ON hybrid_chunks BEGIN
    INSERT INTO hybrid_chunks_fts(hybrid_chunks_fts, rowid, title, section_path, content_text)
    VALUES ('delete', old.chunk_id, old.title, old.section_path, old.content_text);
    INSERT INTO hybrid_chunks_fts(rowid, title, section_path, content_text)
    VALUES (new.chunk_id, new.title, new.section_path, new.content_text);
END;

-- 1.3 轻量本地知识图谱三元组表 (Light GraphRAG)
CREATE TABLE IF NOT EXISTS knowledge_triples (
    triple_id        INTEGER PRIMARY KEY AUTOINCREMENT,
    pod_id           TEXT NOT NULL DEFAULT 'global',
    subject          TEXT NOT NULL,                   -- 主体实体（如 "XX击剑俱乐部" / "U14男子花剑"）
    predicate        TEXT NOT NULL,                   -- 关系谓词（如 "兼项限制" / "报名费用" / "对接负责人"）
    object           TEXT NOT NULL,                   -- 客体实体或属性值
    source_uri       TEXT NOT NULL,                   -- 溯源文档 URI
```

### 4.3 核心算法数学定义与判定规则

#### 1. RRF 融合 + 权威与时间新鲜度重排公式
设词法检索排名为 $\text{rank}_{\text{fts}}(d)$，向量余弦点积排名为 $\text{rank}_{\text{vec}}(d)$，平滑常数 $k = 60$：

$$\text{RRF\_Score}(d) = w_{\text{fts}} \cdot \frac{1}{60 + \text{rank}_{\text{fts}}(d)} + w_{\text{vec}} \cdot \frac{1}{60 + \text{rank}_{\text{vec}}(d)}$$

* **动态意图权重路由**：
  * **精确符号/报错查询**（Query 命中 `CamelCase`、`snake_case`、文件路径后缀或大写错误码）：$w_{\text{fts}} = 0.70, w_{\text{vec}} = 0.30$；
  * **自然语言语义查询**（默认代码/知识库提问）：$w_{\text{fts}} = 0.30, w_{\text{vec}} = 0.70$；
  * **L5 实战微经验检索**：$w_{\text{fts}} = 0.45, w_{\text{vec}} = 0.55$。

叠加权威等级权重 $W_{\text{authority}}$ 与时间新鲜度因子 $W_{\text{freshness}}$：

$$\text{Final\_Score}(d) = \text{RRF\_Score}(d) \times W_{\text{authority}} \times W_{\text{freshness}}$$

* **权威权重 $W_{\text{authority}}$**：
  * `authority_tier == 1`（正式发布库 / 定稿目录）：$1.25$
  * `authority_tier == 2`（当前工作区活跃文件）：$1.00$
  * `authority_tier == 3`（文件名/路径命中 `draft`、`草稿`、`backup`、`archive`、`旧版`、`2024/2025` 等）：$0.60$
* **时间新鲜度因子 $W_{\text{freshness}}$**：
  * 当同一 `topic_cluster_id` 下存在多份文档时，`effective_time` 最新的版本标记为 Head（$W_{\text{freshness}} = 1.20$），其余旧版本自动更新 `is_superseded = 1` 并衰减为 $W_{\text{freshness}} = 0.45$。

#### 2. 多维动态置信度评分公式（`ConfidenceEvaluator`）

$$C = 0.40 \cdot S_{\text{retrieval}} + 0.25 \cdot S_{\text{authority\_consistency}} + 0.20 \cdot S_{\text{critic\_pass}} + 0.15 \cdot S_{\text{tool\_grounding}}$$

* $S_{\text{retrieval}} \in [0, 1]$：Top-3 命中切片的归一化相关度均值（纯对话无检索需求时默认 $0.90$）；
* $S_{\text{authority\_consistency}} \in [0, 1]$：命中证据均为最新正式版（Tier 1/2 且无版本冲突）取 $1.0$；命中旧版草稿或存在跨文档数值冲突时降至 $0.45$；
* $S_{\text{critic\_pass}} \in [0, 1]$：Self-Critique 一次通过取 $1.0$，经重写修正后通过取 $0.75$，仍存疑取 $0.30$；
* $S_{\text{tool\_grounding}} \in [0, 1]$：工具调用均成功且无缺失报错取 $1.0$，存在降级/部分缺失取 $0.50$。

**门控响应策略**：
* **$C \ge 0.85$（高置信）**：正常流式输出交付，底部显示单色高置信徽标（如 `置信度 0.92`）。
* **$0.60 \le C < 0.85$（中置信）**：正常交付，但底部自动附加单色提示条（如 `置信度 0.74 · 部分依据存在多版本差异或间接推理，建议复核来源`）。
* **$C < 0.60$（低置信拦截）**：在严谨模式下触发 `low_confidence_confirmation` 人工介入确认卡片，明确列出依据不足或冲突点，等待用户点击确认后方可将结论作为正式决策依据。

## 5. Testing Decisions（测试与质量验收决策）

1. **黑盒契约测试原则**：所有测试均针对公开类方法、数据库状态变化与工具 JSON 返回结构编写断言，不耦合内部私有向量计算细节。
2. **极限离线与降级验证**：必须在无外网、无 Ollama、无本地 ONNX 缓存环境下验证三级降级链路，确保混合检索引擎无缝回退至纯 FTS5 且返回正常结果。
3. **打包体积与资源红线门禁**：
   * `requirements.txt` 引入 `onnxruntime` 与 `tokenizers` 须采用轻量 CPU 发行版，严禁引入 `torch`、`tensorflow`、`scipy` 等重型包；
   * PyInstaller 打包基础可执行文件增量必须严格控制在 **`< 35 MB`** 以内；
   * `bge-small-zh-v1.5-int8` ONNX 模型与 `faster-whisper` 语音模型均采用**首次使用按需静默下载至 `~/.agenthub/models/`**，不打入基础分发包。
